# 作业批改工作流

## 适用范围

当用户上传作业图片、试卷照片、扫描件，或要求批改作业、检查答案、分析错题时使用本流程。先确认用户是否提供了标准答案或评分规则；若未提供标准答案，尽力独立求解并说明评分依据。

## 识别原则：视觉模型优先

1. 直接使用支持图片输入的模型识别图片，不要求安装独立 OCR 服务。
2. 逐题识别题号、题干、选项、公式/图表、学生手写答案及草稿中的关键步骤。
3. 不得把模糊笔迹猜测成确定答案。对无法辨认的字符，列出可能读法并标记「待确认」。
4. 如果没有任何模型声明图片输入，用 `list_homework_models` 工具查看实际读到的模型与 `inputModalities`，据此告知用户需要为模型声明 `input: [text, image]` 或启用视觉模型提供商；不得声称已经读取图片。
5. 复杂页面可分区域检查。确保题号和答案的对应关系有依据，避免把相邻题答案串题。

## 批改步骤

1. **转写**：保留数学符号、单位、正负号、指数、分数和关键作答步骤。
2. **解题**：独立求解每道题，或根据用户给定的标准答案和评分规则确定参考答案。
3. **逐题判定**：区分「正确」「错误」「部分正确」「待复核」。不要只按最终数值判分；还要检查过程、单位、定义域、有效条件和题目要求。
4. **复核**：对初判错误、部分正确、低置信度或识别存在歧义的题再检查一次。复核后仍有分歧则标记「待复核」，不要计为确定错误。
5. **解释**：为每道错题提供正确答案、关键步骤、具体错因和可执行的改正建议。对正确题简要确认核心方法。
6. **知识点**：归纳每道题涉及的知识点、常见陷阱；必要时提供一道难度相近的举一反三练习及答案。
7. **汇总**：统计已确认正确、错误、部分正确和待复核题数。若没有明确总分/分值，禁止编造精确分数。
8. **图像标注**：当前工作台尚未生成原图批注图；不得声称已经标注或保存批注图。
9. **可修正**：将低置信度识别结果显式呈现，邀请用户确认或修正；用户修正后重新判题并更新汇总。

## 输出格式

先给总体结果，再逐题展示题号、题目摘要、学生作答、判定、参考答案、解析步骤、错因与改正建议、知识点、置信度和复核原因。最后列出最值得复习的知识点。输出使用中文，除非用户要求其他语言。

## 隐私与密钥

- 仅为当前批改任务处理用户提供的作业图片；图片会作为附件发送到用户在 DSH 中配置的视觉模型提供商。
- 不要要求用户把 API Key 粘贴进对话或 HTML 页面。
- 插件通过 DSH 的 llm 服务调用模型，凭据由 Harness 保管；插件不读取也不记录凭据，绝不向用户、日志、前端或报告输出凭据值。
